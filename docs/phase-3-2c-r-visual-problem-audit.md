# Phase 3.2C-R Visual Problem Audit

## Audit basis

- Baseline: production build captured before Phase 3.2C-R changes.
- Evidence: `audit/phase-3-2c-r/before/`.
- Matrix inspected: 52 full-page screenshots.
- Breakpoints: 1440 × 900, 1280 × 900, 768 × 1024 and 390 × 844.
- Routes: Home, Capabilities, Work, About and Contact in English and Chinese, plus CATL, Changan and Teal representative case studies.
- Severity count before implementation: P0 0, P1 8, P2 8.

No blank page, missing primary section, unreadable navigation or completely failed media asset was found, so there are no P0 defects in the baseline.

## Findings

| ID | Page | Section | Breakpoint | Problem | Severity | Root cause | Recommended fix |
| --- | --- | --- | --- | --- | --- | --- | --- |
| P1-01 | Site-wide | All art-directed media | All | Layout roles such as `16/8`, `16/9`, `4/3` and `4/5` do not reliably control the rendered frame. Similar modules therefore change height according to the source asset rather than the page composition. | P1 | `.art-directed-image` applies profile aspect ratios with `!important`, overriding explicit layout classes. | Make the profile ratio a low-specificity fallback and let an explicit media-role or aspect utility win. |
| P1-02 | Changan case; Teal case; Capabilities | Case hero, visual evidence and media walls | All, most visible at 1440 and 390 | Cool-grey or beige bands occupy large parts of media frames and read as blank or unloaded content. Changan’s hero has two grey bands; Teal’s portrait sequence contains near-empty beige panels. | P1 | Pre-generated `contain` derivatives include background padding, but those derivatives are reused in runtime `cover` compositions. CSS cover cannot remove padding embedded in the bitmap without a role-specific crop. | For cover roles, render the approved unpadded source/mobile source and apply focal-point object positioning. Keep padded derivatives only for deliberate contain roles. |
| P1-03 | About ZH | Hero | 1440 and 1280 | The Chinese H1 breaks into many one- and two-character lines, making the hero unusually tall and visually more aggressive than the English version. | P1 | English-oriented `max-w-[11ch]` and a one-off 7.3vw type clamp are shared with Chinese without a language-aware measure. | Use a shared page-display token with a wider Chinese measure and Chinese-specific line height. |
| P1-04 | Work EN/ZH | Hero mosaic | 390 | Two landscape event images are squeezed into equal narrow columns. Important stage and vehicle information is cropped and neither image reads as the lead proof. | P1 | The mobile mosaic preserves a two-column desktop concept while hiding the two supporting tiles. | Give mobile one dominant landscape proof with one secondary inset or a controlled 3:2 pair; retain the four-part mosaic from tablet upward. |
| P1-05 | Home EN/ZH; Contact EN/ZH | Hero and final CTA | 390 and 768 | Display sizes and measures vary by one-off clamp values. On mobile, some headlines dominate the first viewport while adjacent page displays use a noticeably different scale. | P1 | Page components independently declare `clamp(...)`, line height and letter spacing instead of using a shared hierarchy. | Replace one-off display declarations on canonical pages with named display and section-heading tokens. |
| P1-06 | Capabilities EN/ZH | Capability index and creative-production wall | 768 and 390 | The page becomes an unusually long, visually repetitive stack. Media frames alternate between full-bleed crops and padded assets without a consistent role, weakening chapter distinction. | P1 | Desktop interaction collapses to text-only index navigation, while media grids inherit source ratios and generic auto rows rather than role ratios. | Use consistent chapter spacing and named proof-landscape/proof-portrait/card roles; make the index more compact below desktop. |
| P1-07 | Site-wide | Containers and section transitions | All | Canonical pages use the same 1320px wrapper for every content type. Reading copy, dense facts and cinematic media do not share a stable column logic, producing uneven line lengths and alignment. | P1 | Only one container token exists and there is no declared 12-column composition contract. | Introduce wide, standard, reading and narrow container tokens plus a shared 12-column grid and gutter scale. |
| P1-08 | Work EN/ZH | Featured work | 1440, 1280 and 768 | Featured projects have very large inter-project gaps while their descriptive copy is comparatively small. The sequence feels sparse rather than deliberately paced. | P1 | `space-y-24/32` is combined with bottom-aligned copy and source-driven media heights. | Bind rows to stable proof ratios, reduce the cadence to the shared section scale and strengthen the project-title/body hierarchy. |
| P2-01 | Home EN/ZH | Selected UK activity | 1440, 1280 and 390 | The fourth card is outside the initial viewport; the rail has no persistent visual cue explaining that more evidence is available. | P2 | Horizontal overflow is relied on as the only discoverability signal. | Preserve the rail but show a deliberate partial next card and a concise scroll cue/position indicator. |
| P2-02 | Home EN/ZH | Outcomes | 768 | The copy column and media column are close in visual weight, so the selected state does not read decisively at first glance. | P2 | Fixed 0.82/1.18 columns and a generic 620px media minimum are used at the tablet breakpoint. | Delay the split until the content has enough width or use a stronger 5/7 column relationship. |
| P2-03 | About EN/ZH | What we bring | 1440 and 1280 | Four short principles occupy tall cells with large unused areas. The section is longer than the information needs. | P2 | Each item has a fixed 16rem minimum height and a 4rem title offset. | Use the shared compact-section spacing and a denser two-by-two rhythm without changing the copy. |
| P2-04 | Contact EN/ZH | Form section | 1440 and 1280 | The contextual copy occupies a narrow column while the form spans most of the page, creating a weak left edge and an oversized empty lower-left area. | P2 | The form grid uses a 0.58/1.42 split independent of the standard column system. | Place the context on four columns and the form on eight columns with a reading-width inner form. |
| P2-05 | Case studies | Facts and narrative | 1440 and 1280 | Metadata and narrative copy are small relative to the large hero and gallery, so the commercial story recedes behind the imagery. | P2 | Generic 12–16px styles are used across facts, evidence labels and narrative blocks. | Apply the shared label, body and lead tokens and cap narrative line length. |
| P2-06 | Teal case | Visual evidence | 768 and 390 | Consecutive portrait frames have inconsistent widths and heights, creating accidental rather than editorial rhythm. | P2 | Gallery column span logic alternates by index but does not consider source orientation. | Assign landscape, portrait and detail roles from media metadata, with stable mobile ratios. |
| P2-07 | Home; About; Capabilities | Section headings | All | Similar section-level headings use both `.editorial-heading` and several custom clamp declarations, causing inconsistent cap height and line spacing. | P2 | Type styles are coupled to individual modules. | Consolidate canonical section headings on one token and use measure modifiers only where language requires them. |
| P2-08 | Site-wide | Mobile vertical rhythm | 390 | Several consecutive sections use nearly identical top/bottom padding despite very different density, making long pages feel mechanically spaced. | P2 | Mobile `.section-y` is a single broad clamp and components add independent margins. | Use a small documented spacing scale with standard, compact and immersive section variants. |

## Scope guardrails

The audit does not propose changes to positioning, information architecture, service architecture, proof claims, navigation labels, project selection, governance language or CTA strategy. All recommended fixes are presentation-system corrections.
