# Phase 3.4 Release Readiness Plan

Date: 18 August 2026  
Baseline command: `npm run validate:release:production`  
Baseline result: 14 passed, 28 failed, 7 human confirmations required

This plan separates the canonical Phase 3 production surface from permanently redirected source systems. A build pass is not release approval.

## Classification

- **A — CANONICAL RELEASE BLOCKER:** a defect in the current customer-facing production path that Codex can safely correct.
- **B — HUMAN INFORMATION REQUIRED:** relevant to canonical release but dependent on verified owner, legal, infrastructure or live-delivery input.
- **C — LEGACY / RETIRED SYSTEM GATE:** protects a source system whose public URLs are permanently redirected.
- **D — VALIDATOR DEFECT / SCOPE MISMATCH:** tests a non-canonical data or media system as though it powered the Phase 3 website.

## Latent validator defect

When `PUBLIC_WORK_MODE=portfolio`, the validator currently inspects `content/cases/index.ts`, which contains concept scenarios, rather than the canonical `content/portfolio.ts` registry. It would therefore reject the real nine-case portfolio even after human approval. Phase 3.4 must validate the canonical portfolio contract separately and retain concept checks as non-canonical truth checks.
